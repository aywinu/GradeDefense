NEW section 1.7 "Semester campaign waves" (add it to tasks.md under Phase 1, then implement it). This REPLACES the 7-day filter in src/core/wave.ts. Review finding: with the demo data only 3 items are due within 7 days, all exams, so the waves are boring.

Design:
- The campaign walks through the remaining semester week by week. Wave k (1-indexed) covers items due in [ (k-1)*7, k*7 ) days from `now`. Ungraded overdue items (days < 0) join wave 1 as "overdue" (they are angrier: +25% speed).
- `campaignLength(semester, now)` = number of weeks until the last ungraded item (min 1, max 10). Surviving the final wave = semester saved (victory).
- Each item becomes a "spawn group" (one main creature + escorts), so waves feel like a horde:
  - assignment → 1 shambler + 2 "draft" minions (low hp swarmers)
  - quiz → 4–6 swarmers (count from points)
  - exam → 1 boss + 6 "topic" minions spawned in two pulses
  - project/presentation → multi-phase enemy (phases = 3) + 3 minions
  - Escort count scales gently with points (cap so a wave stays under ~40 creatures).
- Wave 1 must be the gentle tutorial: if the real wave 1 is too heavy, cap it at one shambler group plus a few minions and push the rest to wave 2.
- Enemies carry a `lane` index (course index) instead of pixel x/y; the renderer maps lanes to pixels. Add `spawnDelayMs` so a wave enters over ~20–40 s, not all at once. Add `label` (item name) and `daysLeft` for the floating scroll. Minions carry the parent item name too.
- Keep everything pure and deterministic (pass `now` and `rng`; provide `mulberry32(seed)` in src/core/rng.ts).
- Update types.ts accordingly (remove x/y/pathProgress from the pure model if needed; keep `progress` 0..1 along the lane).
- Update wave tests and property tests: every spawned creature references a real item; wave sizes ≤ 40; campaignLength in [1,10]; deterministic for the same seed; every ungraded item appears in exactly one wave across the campaign.
