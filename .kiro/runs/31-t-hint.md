Judge hint ("lantern hint") on every question card. Judges and first-time players do not know the course answers, so each question card gets a Hint button that reveals which choice is correct, so anyone can see what happens when they answer everything right (seals breaking, a creature falling, a passing transcript).
1. Create src/ui/hint.ts exporting `hintButtonHtml(): string` (a small `<button class="hint-btn" data-hint type="button">` labelled "Hint" with a `<span class="dd-kbd">H</span>`, aria-label "Hint: show the correct answer") and `wireHint(root: HTMLElement, correctIndex: number): () => void` that, on click of `[data-hint]` inside root or on the H key, adds the class `hinted` to the `.choice[data-i="<correctIndex>"]` button inside root, disables the hint button, plays sfx('hover'), and moves focus to the hinted choice. It returns a cleanup function that removes its key listener. It must ignore the key once a choice is already disabled (answered). Hints are free: no penalty, the answer logic is untouched.
2. Use it in the three cards: src/ui/TrialPanel.ts (showQuestion, in the g-foot), src/ui/BattleUI.ts questionCard (both 'check' and 'qte' modes, in the qc-foot) and duelCard (in the qc-foot). Call the cleanup wherever the card already removes its keydown listener / is replaced. Keep the existing footer text.
3. Styles in src/styles/ui.css: `.hint-btn` a small muted ghost button consistent with art-direction (no shiny SaaS look), and `.choice.hinted` a faint warm lantern glow outline plus a small "✦" marker via ::after; respect prefers-reduced-motion (no animation then).
4. Add a unit test src/ui/hint.test.ts if the vitest config supports DOM (check vitest.config.ts; if the environment is node only, skip the test and say so).
Verify with `npx tsc --noEmit` and `npm test` (all must pass). Add a ticked task under the UI section of .kiro/specs/deadline-defense/tasks.md: "Lantern hint on every question card (for judges / first-time players)".
